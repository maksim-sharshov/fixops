# FixOps — Самовосстанавливающаяся инфраструктура (React frontend)

Переписанный на React + TypeScript + Vite фронтенд (изначально был реализован в виде одного файла `index.html`). Тот же контракт бэкенда, та же бизнес-логика — новая архитектура, компонентный UI и более профессиональное визуальное оформление поверх существующего дизайн-языка «сдержанного футуристичного инфраструктурного стиля» (quiet futuristic infrastructure).

## Быстрый старт

```bash
npm install
cp .env.example .env   # укажите VITE_API_URL, если бэкенд запущен не по умолчанию
npm run dev

```

```bash
npm run build     # проверка типов + продакшен-сборка в dist/
npm run lint      # oxlint
npm run preview   # локальный просмотр продакшен-сборки

```

## Контракт бэкенда (без изменений)

* `GET   /api/containers`
* `POST  /api/containers/{id}/apply`
* `POST  /api/containers/{id}/rollback`
* `WS    /ws` — сокет мониторинга, сообщает о событиях `job_started`
* `WS    /ws/jobs/{job_id}` — прогресс воркфлоу для конкретной задачи (`job_id`)

Базовый URL задаётся через `VITE_API_URL` (см. `.env.example`), по умолчанию используется адрес, захардкоженный в старом фронтенде (`[http://138.124.240.14:8000](http://138.124.240.14:8000)`). URL-адреса WebSocket формируются автоматически на его основе (`http` -> `ws`).

Новые эндпоинты не создавались. Некоторые эндпоинты, упомянутые в продуктовой спецификации лишь концептуально (например, история инцидентов на стороне сервера, загрузка CPU/памяти по контейнерам), помечены как `TODO` в `src/services/api.ts`, а не додуманы случайным образом.

## Структура проекта

```
src/
  components/    Переиспользуемый UI: Sidebar, cards, Workflow, DiffViewer, LogViewer, ...
  pages/         Overview, Containers, Incidents, IncidentDetail
  layouts/       AppLayout (сайдбар + шапка + контент роута)
  hooks/         useAppState (центральное состояние), useMonitorSocket, useJobSocket
  services/      api.ts — единственное место, работающее с REST API
  lib/           normalize.ts (парсинг событий/diff), workflowSteps.ts
  types/         Общие типы TypeScript, включая размеченные (discriminated) типы WebSocket-событий
  styles/        Дизайн-токены + стили компонентов (чистый CSS, без фреймворков)

```

## Особенности работы (Behavior)

* **WebSockets**: `useMonitorSocket` управляет единственным соединением с `/ws` и автоматически переподключается при закрытии или ошибке (с задержкой 3 с), как и в оригинальной версии. `useJobSocket(jobId)` открывает сокет `/ws/jobs/{jobId}` и формирует всё состояние воркфлоу, ИИ, diff и проверки исключительно на основе полученных событий — никаких искусственных таймеров или сфабрикованного прогресса.
* **Состояние (State)**: инциденты и контейнеры хранятся в едином контексте React (`AppStateProvider`), поэтому индикатор подключения в сайдбаре, статистика на главной странице (Overview) и список инцидентов всегда синхронизированы из единого источника правды.
* **Отсутствие фейковых данных**: показатели CPU/памяти нигде не отображаются, так как бэкенд их в данный момент не предоставляет. Вкладки с ИИ-диагностикой и контекстом рендерятся только тогда, когда бэкенд действительно присылает эти данные.
